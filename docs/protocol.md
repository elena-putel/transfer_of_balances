# Протокол загрузки файлов переноса балансов (.045)

## 1. Общие сведения

Микросервис `transfer_of_balances` принимает пару файлов:
- **файл данных** — `epb{timestamp}.045`
- **файл отчёта** — `epbr{timestamp}.045`

Кодировка: **Windows-1251**  
Разделитель полей: **точка с запятой (`;`)**  
Десятичный разделитель в суммах: **запятая (`,`)**

## 2. Именование файлов

```
epb  + YYYYMMDD + HHMMSS + .045   → файл данных
epbr + YYYYMMDD + HHMMSS + .045   → файл отчёта
```

Пример:
- `epb20260701090706.045`
- `epbr20260701090706.045`

## 3. Структура файла данных

| № | Поле | Тип | Обяз. | Описание |
|---|------|-----|-------|----------|
| 1 | ndog_billing_a | CHAR(20) | Да | Номер договора источника (только цифры) |
| 2 | account_a | CHAR(20) | Да | Лицевой счёт (только цифры) |
| 3 | ndog_billing_b | CHAR(20) | Да | Номер договора получателя (только цифры) |
| 4 | fio_billing_a | VARCHAR(155) | Да | ФИО абонента |
| 5 | summa | DECIMAL | Да | Сумма переноса (запятая как разделитель) |
| 6 | bill_date | DATE | Да | Дата начисления (формат `dd.MM.yyyy`) |

## 4. Структура файла отчёта

| № | Поле | Тип | Обяз. | Описание |
|---|------|-----|-------|----------|
| 1 | fl_file | VARCHAR(22) | Да | Имя файла данных |
| 2 | record_count | INTEGER | Да | Количество строк в файле данных |
| 3 | checksum | DECIMAL | Да | Сумма всех значений `summa` |
| 4 | — | — | Нет | Пустое поле (завершающий `;`) |

### Пример файла отчёта

```
epb20260701090706.045;8;47,6346;
```

Проверка: `-11,2378 + 35,2821 + (-27,9107) + 27,1970 + 0,8218 + (-12,8054) + 12,7755 + 23,5121 = 47,6346`

## 5. Алгоритм обработки

1. Сканирование входного каталога на файлы `epb*.045`
2. Поиск соответствующего файла отчёта `epbr*.045`
3. Парсинг файла отчёта
4. **Fail Fast**: проверка контрольной суммы до сохранения в БД
5. Валидация всех полей каждой записи
6. Сохранение в таблицу `transfer_balance` (с retry через Resilience4j)
7. Перемещение файлов в `processed/` или `error/`
8. Запись результата в `transfer_load_log`

## 6. Маппинг в БД

| Поле файла | Поле БД | Примечание |
|------------|---------|------------|
| ndog_billing_a | ndog_billing_a | |
| account_a | account_a | |
| ndog_billing_b | ndog_billing_b | |
| fio_billing_a | fio_billing_a, fio_askr | |
| summa | summa | Хранится ×10⁴ (DECIMAL(15,0)) |
| bill_date | bill_date | |
| — | type_serv_a | DEFAULT 326 |
| summa | operation | 1 — начисление, 2 — списание |
| — | cod_oper | DEFAULT 45 |
| — | type_enter | 0 — автоматическая загрузка |
| имя файла | fl_file | |

## 7. Дубль-контроль

Уникальный индекс:
```sql
(fl_file, ndog_billing_a, account_a, ndog_billing_b, bill_date, summa)
```

## 8. Примеры ошибок

| Сценарий | Ожидаемый результат |
|----------|---------------------|
| Неверная контрольная сумма | `CHECKSUM_ERROR`, файлы в `error/` |
| Пустое ФИО | `VALIDATION_ERROR` |
| Нечисловой счёт | `VALIDATION_ERROR` |
| Неверная дата | `PARSE_ERROR` |
| Повторная загрузка тех же данных | `FAILED` (нарушение unique index) |
| Отсутствует файл отчёта | `FAILED` |
